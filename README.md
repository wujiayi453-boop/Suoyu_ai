# 索yu

找机会，读新知。岗位、公司、论文、模型与资讯，在这里一起探索。

## 项目的起点

“索yu”是我们三个小伙伴共同完成的信息检索课程项目。确定选题时，我们一直在想：对于想要跟上 AI 发展的人，能不能提供一个更完整、方便探索的信息渠道？

AI 岗位、公司、资讯、论文和模型分散在不同网站，查找和理解这些信息往往需要来回切换。因此，我们希望把它们整理到一起，让用户不仅能找到内容，还能顺着内容之间的关联继续探索。

## 从采集数据到实现检索

确定题目后，我们选取相关网站，使用 Python 进行数据采集，并逐步完成清洗、整理、分析和关联。在这个过程中，我们积累了处理不同数据结构、重复内容和缺失字段的经验，也认识到：检索体验的基础，不只是搜索框，更是数据本身的质量和组织方式。

我们使用 Elasticsearch（ES）建立索引，探索基于倒排索引的检索。受运行环境和分发条件限制，仓库默认版本采用本地检索，保留了连接自有 ES 的配置入口，没有将 ES 服务及其索引一并打包。倒排索引是检索平台的重要基础，也是我们希望继续学习和完善的部分。

## 从数据到一个可以使用的网站

开发过程中，我们采用了 Vibe Coding 的方式，借助AI辅助编写和迭代代码，同时也自己阅读、修改了不少代码，反复调整页面结构、数据展示和交互细节。

我们使用 VS Code、Node.js 和 GitHub 完成开发、运行与版本管理，结合 frontend-design、Taste Skill、Impeccable 等 Skills，并参考 Taste Engine 的 Fortune 设计分析，逐步统一网站的字体、配色、间距和动效。在参考之外，也融入了我们对“索yu”的思考，包括品牌标志、不同板块的主题、首页统计、侧边导航，以及内容之间的关联方式。

## 我们希望它带来什么

索yu旨在将分散的 AI 岗位、公司、资讯、论文和模型连接起来，帮助用户更高效地寻找机会、了解行业和探索技术。

对我们来说，这既是一次提升数据处理、信息检索和开发能力的实践，也希望能为有类似需求的伙伴提供一些思路。我们想做的，是让那些希望跟上 AI 发展的朋友，多一个集中获取信息、继续深入探索的入口。

## 接下来

项目还有不少需要改进的地方，包括检索效果、数据关联、内容完整性和使用体验。欢迎大家试用，也欢迎提出建议，帮助我们发现遗漏和不足。

希望大家喜欢“索yu”。这不会是我们的最后一个项目，我们会带着这次积累的经验，继续学习、继续尝试，也继续把想法做出来。

## 1. 首页

首页提供平台概览和各类内容入口。

- **搜索区**：输入关键词，查找感兴趣的内容。
- **数据统计**：通过环形图展示五类内容数量，支持数字动效。
- **侧边导航**：快速跳转到机会、团队、资讯和研究板块。
- **内容推荐**：展示岗位、公司、资讯以及论文和模型。

## 2. AI 岗位页

集中展示 AI 相关岗位，方便寻找和比较机会。

- 支持关键词搜索、条件筛选和排序。
- 展示岗位名称、公司、地点等信息，具体以数据源为准。
- 点击岗位可阅读详细要求，并查看相关内容。

## 3. 公司页

用于了解 AI 相关公司及其业务方向。

- 支持搜索和筛选公司。
- 展示公司介绍、业务领域等信息。
- 从公司详情继续探索相关岗位和其他资料。

## 4. AI 资讯页

用于浏览 AI 行业动态和专题内容。

- 支持关键词检索、筛选和排序。
- 列表展示标题、摘要及来源等信息。
- 点击进入正文，查看相关实体和原始来源。

## 5. AI 论文页

用于查找和阅读 AI 研究资料。

- 支持论文检索与筛选。
- 展示标题、作者、摘要等信息。
- 详情页提供已有正文及来源链接，便于进一步阅读。

## 6. AI 模型页

用于了解 AI 模型及相关技术资料。

- 支持模型搜索与排序。
- 展示模型名称、介绍和相关信息。
- 可进入详情查看资料，并探索关联内容。

## 7. 综合搜索页

将五类内容放在同一个搜索入口中。

- 输入关键词，查找跨类别的信息。
- 按内容类型查看结果。
- 从结果直接进入详情或收藏内容。

## 8. 内容详情页

岗位、公司、资讯、论文和模型分别使用适合自身内容的详情布局。

- **主要信息**：展示标题、来源及类别信息。
- **正文区域**：阅读完整的已有内容；源数据缺失时显示提示。
- **关联内容**：展示数据中有依据的关联，方便继续探索。
- **收藏与来源**：保存感兴趣的内容，或跳转原始页面。

## 9. 我的收藏页

集中管理个人保存的内容。

- 通过照片式卡片和列表浏览收藏。
- 支持切换、拖动、进入详情和取消收藏。
- 没有收藏时显示引导提示。

收藏保存在当前浏览器中，不会自动同步到其他设备。

## 已经有完整项目？直接打开，不用重新下载

| 打开方式 | 怎么操作 | 怎么停止 |
| --- | --- | --- |
| 双击启动（Windows） | 在项目文件夹双击 `启动.bat`，浏览器自动打开 | 关闭启动窗口 |
| VS Code 一键运行 | 文件 → 打开文件夹，选择包含 package.json 的项目根目录；按 F5，选择“索yu：一键启动” | 按 Shift+F5 |
| VS Code 任务 | 终端 → 运行任务 → 索yu：启动网站 | 终止该任务 |
| 终端启动 | 在项目根目录运行 `npm run open` | 按 Ctrl+C |
| 固定端口启动 | 运行 `npm start`，浏览器打开 http://127.0.0.1:4173/ | 按 Ctrl+C |

前四种方式会检查完整数据、自动选择空闲端口；Windows 上会自动打开浏览器，其他系统请打开终端显示的网址。固定端口方式适合已确认数据齐全的使用者。

## 首次下载

已有完整文件夹的用户跳过本节。首次获取完整项目需要 [Git](https://git-scm.com/downloads) 和 [Git LFS](https://git-lfs.com/)。Git for Windows 通常包含 Git LFS。

在 VS Code 的“终端 → 新建终端”中依次运行：

```bash
git lfs install
git clone --depth 1 https://github.com/wujiayi453-boop/Suoyu_ai.git
cd Suoyu_ai
git lfs pull
npm run open
```

`--depth 1` 只获取最新版本，避免下载旧提交历史。完整原始数据约 1.3 GB，本地完整运行仍需保存这些数据；Git/LFS 还会保留缓存，请预留至少 4 GB 空间。首次下载完成后，平时启动不会重复下载已有完整数据。

也可以使用 VS Code 的“Git: Clone”命令克隆仓库，再打开下载好的文件夹；这种方式同样需要 Git 和 Git LFS，并可能获取更多历史。

不推荐只用 **Download ZIP**：源码压缩包可能只有 LFS 占位符，无法保证完整正文。启动器会识别此情况并提示，不会把占位数据当成完整数据运行。

## 更新项目

关闭正在运行的网站。在项目根目录的终端依次运行 `git pull --ff-only` 和 `git lfs pull`，然后重新启动。有自己修改的代码时，先保存或提交更改；遇到冲突不要直接覆盖文件。

## 常见问题

- **没有 Node.js**：双击启动会打开官网；安装 LTS 后重新启动。
- **数据未下载完整**：在克隆的项目里，启动器会尝试执行 Git LFS 下载；失败时检查 Git/LFS 和网络，再重试。
- **网页没有自动打开**：复制终端显示的网址。自动启动使用空闲端口，每次可能不同。
- **固定端口被占用**：使用 `npm run open` 或 F5 启动。
- **关闭终端后打不开网页**：重新启动网站，运行期间保留启动窗口。

内容、搜索和关联功能使用完整本地数据。外部封面图片和来源链接仍需要网络。启动器不会自动安装软件或修改系统设置。

## 开发与维护

## 目录结构

```
public/     前端静态资源（index.html、css/、js/），由服务直接对外提供
src/        后端代码（config / utils / services / app.js / server.js）
database/   raw/ 原始 JSONL、generated/ 构建产物、mapping/ ES 映射
scripts/    数据构建、ES 导入、冒烟测试、ES Mock
docs/       产品说明、使用说明、架构与重构记录
logs/       运行与验证日志
```

## 数据流

1. 未配置 Elasticsearch 时：服务启动加载 `database/generated/data-full.js` 全量摘要索引，
   详情页按 `database/generated/*-offsets.json` 的字节偏移，从 `database/raw/*.jsonl` 直读正文。
2. 配置了 `.env`（`ES_URL` + `ES_API_KEY`）时：走 Elasticsearch 实时查询，失败自动回退本地索引。

## 常用命令

| 命令 | 作用 |
| --- | --- |
| `npm start` | 启动服务（http://127.0.0.1:4173） |
| `npm run build-data` | 从 `database/raw/` 重建 `public/js/data.js`、`database/generated/data-full.js` 与两个偏移索引 |
| `npm run import:es` | 把原始 JSONL 导入本机 Elasticsearch（需要 `ES_ADMIN_PASSWORD`） |
| `npm run smoke` | 冒烟测试，抓取 API 与静态资源快照 |
| `npm run mock:es` | 启动 Elasticsearch Mock（离线验证 ES 模式用） |
